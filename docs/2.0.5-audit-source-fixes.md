# 2.0.5 audit fixes — source work, not a release

The 2.0.6 / version-code-8 source includes the previously requested minimal interface and the five audit fixes. Android device behavior has not yet been exercised; consult the specific build's results before claiming its APK passed. The old audit and its evidence describe the pre-fix source; the historical reproducers in `scripts/audit-*` intentionally assert the old behavior.

## Changes

1. **Recorder worker:** the Android worker records read, write, close, and flush failures, retains the partial original and immediately emits a session-specific failure event. Its foreground notification changes to a failure message; the screen also checks native worker status as a fallback and retains Stop. Stop timeouts and failures do not later rewrite the recovery header. The native recorder flag is deliberately left available for the normal Stop/cleanup path.
2. **Recording recovery:** inspecting, previewing, exporting, or reconciling a recording never silently rewrites its header. A mismatch warns that audio may be missing. In Your files, the user can share the original as-is or confirm creation of a separate, integrity-checked repaired WAV in Results. Repair changes only the copied header; it cannot restore missing samples.
3. **Imports:** the incoming copy and any existing digest-named private file are hashed before reuse. A mismatched or unreadable existing file is never overwritten; a verified alternate is selected and a warning is shown. Publishing uses an atomic no-replace hard link. If the filesystem does not support it, the operation fails rather than overwriting data; the incoming source is not changed.
4. **Stop and Back:** the recording screen identifies the current operation, including stopping the recorder, draining live work, checking samples, final audio, WAV preparation, and full-file processing. Host React tests invoke the Back guard during delayed stages. The originally reported Back issue has not been reproduced or diagnosed on Android.
5. **Decoder and trim:** the CommonJS decoder backport uses the upstream 0.5.1 linear approach while retaining 0.2.x plus-to-space behavior. The lockfile still names 0.2.2, so package-version audit tools may continue to report the advisory despite the source patch. PCM trimming applies short cut-edge fades for single and multiple segments against the true source length, including overlapping short fades. Trim is optional and may still remove quiet speech or meaningful pauses.

## Checks and remaining work

Passed on the host: the Node/React regression suite, TypeScript and lint checks, an isolated frozen dependency install with all seven patches, byte-for-byte checks of the installed recorder and decoder patches, the real bundled CPU model comparison, Java safety tests, and extracted Kotlin worker/trim-dispatch tests. An Android-target Metro export also passed; it is a JavaScript bundle, not an APK or native compilation. Host tests do not prove Android behavior, audio quality, hardware failure recovery, or lifecycle behavior.

Before release: compile and build an Android APK only after approval; test recording, pause/resume, Stop, app-arrow and system Back during every stage; inject read/write/flush failures, storage-full and process-kill cases; verify that the notification changes, files stay intact, repair produces a separate copy, and concurrent imports cannot overwrite; and listen to short and long trimmed cuts on the target phone. Test hard-link support on the target filesystem. Reconfirm signing, version/code, size and checksums before delivery. Keep independent backups for important recordings.

Shizuku remains optional and is not part of these fixes.
