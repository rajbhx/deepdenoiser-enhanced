# Dependency security review (2026-10-29)

`bun audit --json` against the locked install reported three package advisories. An audit result is not a full Android/native vulnerability assessment, and severity alone does not establish exploitability in this app. Re-run the audit and review the exact release APK and its Gradle/native graph before any production distribution.

| Package / advisory | Finding and status in this tree |
| --- | --- |
| `decode-uri-component@0.2.2`, [CVE-2026-45822](https://github.com/advisories/GHSA-vcc3-ghjq-m6fr), moderate | Expo Router's `query-string@7` uses this CommonJS package. The vulnerable recursive malformed-percent decoder has been replaced via `patches/decode-uri-component+0.2.2.patch` with the upstream 0.5.0 UTF-8 decoding fix, retaining the 0.2.x CommonJS API and `+`-to-space behavior. External route paths are also bounded before router query parsing; native share payloads remain in their separate bounded queue. Tests exercise query behavior and long malformed strings. Upstream 0.5.0 is ESM and is not a drop-in CommonJS override for query-string 7. The lockfile still identifies version 0.2.2, so version-based scanners will **continue to report it**; keep the patch and tests until a compatible supported upgrade is verified. The official decoder's outer replacement logic is not a proof of strictly linear total runtime for all inputs. |
| `zod@3.25.76`, [CVE-2023-54404](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5), high | The broad advisory reports versions below 4.6.6. The locked v3 instance is required by Expo CLI, a build-tool path; the separate `zod@4.6.7` instance is above the patched threshold. The v3 API and Expo's v3 requirement make a forced v4 override potentially breaking. Confirm applicability to the particular v3 code path, build exposure and any upstream backport or compatible Expo upgrade. Do not accept untrusted build inputs; no compatible fix is asserted here. |
| `deepmerge@4.3.1`, [CVE-2026-93753](https://github.com/advisories/GHSA-gcqx-w48m-w2h4), low | Reached through `@expo/config`; the advisory lists no patched version. Review whether untrusted objects ever reach the relevant merge in the build and shipped application; use trusted configuration and monitor upstream. No fix is claimed here. |

The first issue has a tested source-level mitigation, **not** a clean version-based audit. The other two remain open review items. Verify CI installs the committed patches successfully, rerun tests after dependency changes, and avoid exposing build tooling to untrusted inputs. A production release remains gated on the larger model/license, native-notice, signing, privacy and device review in `THIRD_PARTY_REVIEW.md`.
